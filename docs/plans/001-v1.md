# Rails CVE v1

## Product
An independent opt-in Rails security relay at rails-cve.avi.nyc. Help a maintainer move from an advisory to a reviewed investigation. Never claim to detect exploitation or automatically patch production. Rails red, warm cream, restrained typography, public advisory index and details, one clear connection flow.

## Source decision
Use https://api.github.com/repos/rails/rails/security-advisories as canonical structured input. It currently returns 26 published advisories. Poll every five minutes, follow pagination, validate records, preserve the canonical URL and exact version strings. Published updates create new revisions. Initial import is a quiet baseline, not a historical notification storm. Google Groups is useful as an optional wake-up signal; incoming email never supplies trusted advisory content. rorsecurity.info is an independent educational resource, not the canonical advisory feed. The first version covers rails/rails, not every Ruby ecosystem gem.

## Build sequence and acceptance
1. Initialize git; add Bun, Hono, Worker static assets and D1. Configure isolated resources and the custom domain; never reuse another application’s data or secrets.
2. Add migrations for accounts, endpoints, advisories, immutable events, delivery outbox and sync state. Unique revision and endpoint/event keys prevent duplicate enqueueing.
3. Normalize GitHub data; retain package ranges, patched versions, publication/update dates, withdrawn flag and description. Fetch complete pages before ingest. Lock concurrent syncs; persist sync health. Retry failed sync next cron.
4. Provide public index, search/severity filters, detail pages, JSON API and per-advisory SKILL.md. Include curated Rails forensic toolkit link for CVE-2026-66066. Prompts distinguish upstream data from instructions, require repository evidence, and request approval before remediation or production access.
5. Use a 256-bit management token for a small account; store only its hash. Browser uses an HttpOnly SameSite=Strict cookie, restores via token, supports logout. No email provider or OAuth application required. Show recovery token once; lost token requires a new account.
6. Register named HTTPS endpoints. Reject credentials, fragments, non-443 ports, local/private/reserved IPs and DNS answers; never follow redirects. Verify endpoint ownership via challenge echoed in plain-text response. Encrypt signing secrets with AES-GCM and a Worker secret.
7. Deliver versioned JSON with stable event ID and HMAC-SHA256 over timestamp + '.' + raw body. Use durable D1 outbox with atomic leases; bounded cron batches, timeout, exponential retry, dead state after 8 attempts. Receivers must verify freshness and deduplicate event IDs. Recheck destination before every request. Pause/resume/delete and test delivery from dashboard.
8. Document receiver verification with executable Ruby example, endpoint challenge, credential recovery, operational limits, monitoring, email routing setup and deployment.
9. Test crypto, destinations, normalization, authentication isolation, ingestion idempotency, retries and public/UI flows. Verify desktop/mobile with agent-browser. Deploy D1 migrations, secrets and Worker, import live advisories, verify real custom hostname.

## Operational choices
D1 serves as durable outbox in v1 so a queue handoff cannot lose a committed event. Cron drains at most 25 deliveries per run in small parallel batches. For larger traffic, add Queues as a wake-up layer over the same durable outbox, preserving reconciliation. At-least-once delivery; no ordering guarantee. New endpoints receive future events plus an explicit test, not an automatic replay of history. Pending endpoints receive only explicit verification requests.

## Later increments
- GitHub App identity, team ownership, recovery and API key rotation.
- Broader RubySec coverage, package/version subscriptions and Gemfile.lock matching.
- Queues for lower latency and scalable fanout; operator replay and retention controls.
- Opt-in repository agent integrations opening reviewed PRs; never silently merge or deploy.
- Independently authenticated email routing and curated upstream investigation skills for more CVEs.
